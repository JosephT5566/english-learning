## 2026-08-28 - Current-state auth, vocabulary, and review trace

### Outcome

- Documented the three current request flows and their browser, Google Identity Services, Apps Script, and Google Sheets boundaries.
- Inventoried all 21 observed Sheet headers and distinguished conventions from enforced constraints.
- Added a synthetic sanitized fixture for future contract and migration tests.

### Decisions and reasoning

- Kept this ticket descriptive: no auth, selection, scheduling, Apps Script, or Sheet behavior was changed.
- Chose client-controlled review state as the most important persistence-migration risk. The future backend must verify ownership, accept a review decision, derive scheduling state server-side, and commit the event and current state atomically.
- Treated the public Apps Script read path as a separate current security weakness because it executes as the owner without application authentication.
- Kept the proposed `my-oauth` integration out of the current-state report because it is planned behavior, not current evidence.

### Failures and corrections

- Corrected the initial assumption that auth failures show a dialog: current credential callback errors are logged to the console.
- Corrected the assumption that intended sort comments describe executed behavior. Two sort calls pass zero-based header indexes to one-based `Sheet.sort()`, selecting `intervalDays` and `status` rather than `lastReview` and `reviewStage`.
- Corrected the assumption that `getList` is read-only: it sorts the live Sheet in place.
- An unauthenticated Apps Script runtime probe did not return usable output; a bounded retry timed out after 20 seconds. Deployment inspection separately confirmed access is `Everyone` and execution is as the script owner.
- `npm run check` and `npm run lint` failed; `npm run build` passed with warnings. These results were recorded without treating the successful build as successful type checking.

### Remaining uncertainty

- Blank-cell ordering in the sequential Sheet sorts
- Exact Apps Script exception envelope
- Concurrent Apps Script execution and locking behavior outside the inspected update function
- A signed-in end-to-end review submission was not repeated during this documentation session

### Learning checkpoint

Current review updates send client-calculated card ID, stage, ease factor, and timestamps. Apps Script verifies the user token but trusts the submitted state. The future backend must enforce ownership, calculate the transition server-side, and persist review history plus current state atomically.

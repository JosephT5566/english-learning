## Issue #27 — local request-correlation boundary

- Chose one allowlisted JSON request-completion event keyed by the server request ID and disabled
  Uvicorn's raw-URL access log. The event records route template, status, duration, outcome class,
  and stable error code without request values or identity. Unexpected endpoint exceptions return
  the existing safe envelope inside middleware; a broken log sink cannot change a completed result.
- Local verification passed 109 unit and 147 PostgreSQL integration tests plus scoped Ruff checks.

  Deployed Cloud Run parsing, platform-log privacy/retention, alerts, backup/restore, and the
  incident exercise remain unverified.
- A subsequent read-only Cloud Logging audit found raw request URLs in all 100 sampled platform
  request logs; 21 had query strings. The `_Default` bucket retains entries for 30 days. This
  narrows the privacy claim to the new application event and leaves a proposed service-specific
  request-log exclusion for review after candidate verification.
- A PR CI run exposed a smoke-script false negative when `docker logs | grep --quiet` met
  `pipefail` after the new events increased log output. Capturing logs before checking the
  shutdown marker fixed the test locally; the local image build, full container smoke, and final
  [CI run 35211160518](https://github.com/JosephT5566/english-learning/actions/runs/35211160518)
  passed. The operator deferred publishing and zero-traffic candidate verification, so no deployed
  tracing, alert, or platform-log exclusion is claimed.

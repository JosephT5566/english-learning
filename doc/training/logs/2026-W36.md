# Learning Log - 2026-W36

## 2026-08-31 - Issue #6 backend foundation design

### Decisions and reasoning

- Chose `uv` for the independently buildable Python project under `apps/api/`, with
  `pyproject.toml`, a committed lockfile, and separate runtime and development dependencies.
- Chose to let the API start during a temporary PostgreSQL outage. Liveness remains independent of
  the database, while database-aware readiness returns a safe `503` until PostgreSQL recovers.
- Defined a minimal health response contract that reports database availability without returning
  exception text or connection details.
- Chose typed settings for environment, logging, the database URL, and the readiness connection
  timeout. Local defaults use disposable Compose-only credentials; production must override the
  database URL.
- Distinguished invalid configuration, which fails startup, from temporary database unavailability,
  which leaves the process live but not ready.
- Chose FastAPI lifespan startup and shutdown for database engine construction and disposal.
- Selected the minimal runtime set: FastAPI, Pydantic, pydantic-settings, SQLAlchemy, Psycopg 3 with
  its binary extra, and Uvicorn with standard extras.
- Selected pytest, HTTPX, and Ruff as development dependencies. Deferred Alembic, async test
  plugins, coverage tooling, and Testcontainers because Issue #6 does not yet require them.
- Chose synchronous SQLAlchemy for the initial service. It keeps connection lifecycle and endpoint
  tests small while synchronous FastAPI route functions avoid blocking the event loop.
- Chose a minimal `apps/api/app` package with separate configuration, database, health, and
  application-factory modules. Deferred empty domain-oriented packages until later features require
  them.
- Separated fast unit tests from PostgreSQL integration tests so their dependency and execution
  contracts remain explicit.
- Kept `compose.yaml` at the repository root for shared local infrastructure and API-specific
  environment examples, package metadata, lockfile, and commands inside `apps/api/`.
- Chose an application factory and Uvicorn `--factory` target to avoid settings and database resource
  construction as module-import side effects.

### Verification status

- These are design decisions only. No FastAPI application, Compose service, automated test, or
  successful backend command exists yet.

Scaffold the accepted `apps/api/` boundary and verify the first independently runnable liveness
endpoint before adding PostgreSQL readiness behavior.
